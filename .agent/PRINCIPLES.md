# vndb-skins 设计原则与工作约定

> 这是「已经定下来的规矩」的唯一入口。
> **AI 做主题前先读这里；要改规矩直接改这里，不用翻聊天记录。**
> 每套主题的具体推导放在各自的 css 文件头注释里；调试过程、踩坑记录不写在这里。
>
> ⚠️ **本文件就在 `.agent/PRINCIPLES.md`，仓库根目录不放它** ——
> 要改就改这一份；在仓库根目录另建一个 `PRINCIPLES.md` 只会得到两份不同步的副本。
>
> 最后更新：2026-10-09

---

## 0. 优先级（目标函数）

1. **符合角色颜色**
2. **跟背景图整体不冲突**
3. ~~不追求全都不同~~ —— 明确说了：**不追求"十套全都一眼不同"**，别拿"最大化区分度"当目标。

只有当上面两条都满足时，才去考虑"两套主题太像"的问题。
（曾经为了区分度把颜色改得不像角色，是被否掉的方向。）

> 推论：§3.7 的「60° 色相扇区」也落在这一档 —— **尽力而为**，不得为了它去改底色或角色取色。

## 1. 文件与命名约定

- **每套主题是 `custom/<name>.css`**，`name` = 角色名（罗马字，下划线分词，如 `tobisawa_misaki`）。
- **同一角色的试验版/对照版加 `_2` 后缀**（如 `nikaidou_shinku_2.css`）。
  脚本的 `THEMES` 只收录定稿的那一个；变体不进轮换。
- **每个文件的固定骨架**（顺序别乱，注释要写"为什么"）：
  1. 文件头大注释：用法、取色来源（背景图实测 + 角色立绘，两个来源要互相印证）、背景图出处、实测尺寸、构图、背景显示方式、站标题处理
  2. 第 1 节 调色板 `:root`（变量名全部沿用官方皮肤）
  3. 第 2 节 背景图
  4. 第 3 节 压暗层（薄纱）
  5. 第 4 节 站标题与页脚
  6. 第 5 节 卡片层次感
- **字体/字号一律沿用官方**（Tahoma 13px 正文 / Futura 斜体 24px 站标题），不做改动。
- **只覆盖官方变量，用 `:root` 声明**，特异性 (0,1,0) 高于官方 `html{}` 的 (0,0,1) → **不用 `!important`**。
- 注释里出现的数字（亮度、对比度、色相、比例、宽度）改了颜色/图就要一起改，**不允许留过期注释**。

## 2. 取色原则

- **主色只用"角色身上"的颜色**：发色、瞳色、服饰、随身物。
- **画面的大面积环境色只用来当底色 `--bodybg`**（天空/海/房间暗部的色相，压深到 L 0.14~0.21）。
- 取色要**两个来源互相印证**：① 背景图逐块实测（canvas `getImageData`，可按 HSV 色相分区取 top 饱和像素均值）；② 角色立绘（VNDB 角色页 `t.vndb.org/ch/...`，注意核对正确的立绘 id）。
- **立绘/画面里没有的颜色不要硬编**（比如"画面里没有绿"就明说这是补的相位）。

## 3. `--link` 的硬性规矩

1. **`--link` 必须与 `--bodybg` 同色系**：OKLCh 色相圆周距离 **≤45°** 算同族。
   （当前 20 套全部通过，最大 35.5°（`izumi_hiyori`）。）**这是明确要求，优先于其它推论。**
2. **同族之后，分离只靠明度和彩度**：
   底色 L 0.14~0.21、低彩度 ↔ 链接 L 0.74~0.81、彩色 → 对比度 ≥8:1。
   **改底色或链接时这两个量要一起看，别只动一个。**
3. **house style**：link OKLCh ≈ `L 0.74~0.85 / C 0.09~0.15`；色相基本不动，只调 L/C。
4. **硬指标**（必须满足）：
   - `ΔE00(link, --maintext) ≥ 22`
   - `ΔE00(link, --grayedout) ≥ 18`
   - `contrast(link, --bodybg) ≥ 8`
5. **调"清淡"不要连明度一起大改** —— 判断依据用「与 `--maintext` 的 ΔE00 ≥ ~22」，
   比"看起来淡不淡"可靠。（曾经把彩度 0.153→0.076 且明度 0.72→0.80，观感糊进正文。）
6. **`--helpbutton` 恒等于 `--link`。**
7. **色相分布：尽力而为（不是硬指标）** —— link 色相**尽量**每 60° 扇区不超过 2 套；
   同扇区两套的 `--bodybg` 色相差**尽量** ≥60°。
   ⚠️ **2026-10-07 已明确降级**：这是"能顺手避开就避开"的偏好 ——
   **不得为了它去改底色或角色取色**，§0（先符合角色、再与画面不冲突）和 §3.1（link 与底色同系）都排在它前面。
   当前实况（20 套，2026-10-09 从 css 现算，按 link 色相）：
   180–240° **6 套**、240–300° 4 套、300–360° 4 套、0–60° 3 套、60–120° 2 套、120–180° 1 套。
   同扇区底色最接近的其实是老主题：`arise_kaguya` 287.3° vs `yugyouji_yoruko` 288.7°（**1.3°**）、
   `izumi_hiyori` 344.5° vs `naitou_maia` 346.2°（1.8°）、`nikaidou_shinku` 261.3° vs `sorakado_ao` 258.4°（2.9°）。
   2026-10-09 追加的两套排在 6.2°（`umino_miyako` 24.5° vs `yonagi` 30.7°）
   与 7.1°（`ayase_aisa` 337.4° vs `izumi_hiyori` 344.5°）**之后** —— 不是最挤的那一对。
   原因：底色由背景图决定，而这批图的底色本来就都落在青蓝、粉紫两带。
   加新主题时照常先满足 §3.1 与 §3.4，最后再顺手看一眼扇区分布即可。
8. ⛔ **不能为了让某套用"角色标志色"当链接，把底色也挪过去** —— 会挤掉已经占住那个色相族的另一套。
   金色族已被 `koizuka`(琥珀) + `tobisawa`(黄绿) 占满，就是这个原因。

## 4. 角色色该放在哪个变量上

- **人物标志色如果是"外族"（跟底色不同色相），不要放在 `--link` 上** ——
  放到 `--boxtitle` / `--standout` / `--statnok` 这些显眼角色上。
  （例：nikaidou 金发红瞳 → 标题金 + 强调珊瑚/洋红 + status 正红。）
- **某套"同族链接撞车"时，出路通常是"把链接的旧颜色让给某个亮档角色"**
  （izumi 的金 → `--boxtitle`；arise 的紫 → `--alttitle`）。
- `--standout` = **全站最跳的一档**，若要和 link 拉开**必须跳出底色那一族的色相**
  （同族里最多只能到 ΔE ~20）。
- **红档留给 `--statnok`（+ `--warnborder`）**：`--standout` 不要用正红。
  （官方给 `.standout` / 表单 invalid 的是 `#e44`，本仓十套早就不是红了。）
- `--boxtitle` 与 `--standout` **不能同色相**（曾经金标题 + 金强调只差 ΔE 5）。
- `--alttitle` 与 `--boxtitle` **同族提亮**，靠明度分主次。
- `--grayedout` 不要偏成链接那一族（链接占了的色相，弱化文字再进去就撞）。

## 5. 背景图几何

- **宽度是唯一主变量**：`--theme-bg-w`；高度 `--theme-bg-h: calc(var(--theme-bg-w) / (原图宽 ÷ 原图高))`。
  换图后系数必须重算（写大了渐隐层比图矮，下缘露硬边）。
- **实测尺寸以"实际下发的那张文件"为准**：文件名里的 `@1192w` / `@1192w_1490h` 后缀**可能是陈旧的**（图被裁过但没改名）。
- **淡出侧 = 被页面边缘包住的那一侧**：
  - 图贴左上 (`--theme-bg-pos: left top`) → 淡出**右边 + 下边**（`to left` / `to top`）
  - 图贴右上 (`right top`) → 淡出**左边 + 下边**（`to right` / `to top`）
  - **位置和渐隐方向必须成对改。**
- **两层渐隐层的尺寸都要比图片各外扩 4px**：`calc(var(--theme-bg-w) + 4px) calc(var(--theme-bg-h) + 4px)`。
  这是修"小数像素边缘亮线"的，**别删**（渐变层在整数像素上会露出一条原图亮边）。
- 用 `background-attachment: scroll`（图属于网页，随页面滚走，不跟着视口）。
  此时尺寸**只能用 vw/vh/px**，不能写 `contain` / `cover` / 百分比（会按整个文档高度算，长页面会炸）。
- **渐隐深度**：横向 `--theme-bg-fade`、纵向 `--theme-bg-fade-y` 是**两个独立的数**，不要合并。
  12%~16% 都安全；亮图（四缘亮度 150+）才需要 20%~28%。18% 以上开始明显吃画面。
- **渐隐曲线必须是 smoothstep（9 档），不能用两端线性** ——
  线性在图片边界上斜率突变，眼睛会看到一条硬边（马赫带）；加宽渐变治不好。
- 两份 fade stops 里的 `rgba(R, G, B, α)` **RGB 必须等于 `--bodybg`**；`--bodybg-0` 同理。
- 站标题让位（**2026-10-07 起 20 套统一成这一条，没有"两套写法"了**）：

  ```css
  /* 图在右 right top；图在左就把两条 padding 和两个撑杆的权重对调 */
  body > header h1 {
    padding-right: calc(var(--theme-bg-w) + var(--title-gap) - 10px);   /* 让出图片之外那块区域 */
    padding-left: 0;                                                    /* ⚠️ 必须写，见下面 */
  }
  body > header h1::before { content: ""; flex: calc(1 - var(--title-pos)) 0 0; }  /* 远离图那侧 */
  body > header h1::after  { content: ""; flex: var(--title-pos) 0 0; }            /* 靠图那侧 */
  ```

  - 语义：标题落在「图片之外那块区域」里、**从图片一侧量起的 `--title-pos` 处**
    （图在左就从左算、图在右就从右算），并与图片至少留 `--title-gap`。
  - 两个零宽撑杆按 `(1 − pos) : pos` 瓜分空档 —— 撑杆只吃 flex 空档（`flex-basis: 0` + grow），
    **所以不需要知道标题有多宽**，VNDB 改文案/字号都不用动公式。
  - `--title-pos` 就是那条可调参数：`0` = 贴着图、`0.5` = 居中、`1` = 贴到另一头。当前 **0.167（1/6）**
    （⚠️ 2026-10-08 由 0.333 改成 0.167；20 套的 `:root` 里都是这一个值。
     旧文件注释里还写着"当前 1/3"的那几处是漏改的文字，**以 `--title-pos` 的实际值为准**）。
    实测（`misakura_rin`，1512 宽，空档 512px）：`0 → 44px`、`0.167 → 129.5px`、`0.25 → 172px`、
    `0.333 → 214.5px`、`0.5 → 300.1px`、`1 → 556.2px`，全部与公式 `44 + pos × 空档` 一致。
  - 最小空隙实际是 **`--title-gap + 20px` = 44px**（`- 10px` 是替窄屏的 body 内边距 10px 扣的，宽屏因此多 20px）。
    当前 1/6 下各档实际空隙：42vw → 129.5px、40vw → 134.6px、38vw → 137.7px、32vw → 167.8px、25vw → 172.5px。
  - ⚠️ **`padding-…: 0` 那条不能省**：官方规则只管 `padding-right`（`max(30px, calc(100% - 700px))`）。
    图在左时若不清掉它，内容盒会被两侧同时挤 —— 实测 1512 宽下只剩 51px，标题断成 3 行、空隙掉到 17.5px。
  - ⚠️ 窄屏：空档会被图片吃掉，标题先折行、最后贴着 `--title-gap` —— **不会再压到图上**（旧写法是允许压图的）。
  - ⛔ 不要再写 `justify-content: center`（撑杆已经接管定位）、不要再写
    `min(图片宽 + 10px, 100% − …)` 这种封顶变体、也不要掺 `calc(100% - 700px)` 的官方位置 ——
    它们要么做不到"可调分数定位"，要么让标题停在离图很远的老位置
    （`himeno_towa` 曾约 200px、`izumi_hiyori` 曾约 460px）。
  - 页脚/其它压在图上文字仍按老规矩：窄屏允许压图，靠 `text-shadow` 保证可读。

## 6. 改一个变量的连带清单（最容易漏）

改 `--bodybg` 时**必须一起改**：

1. 安静层 7 条：`--boxbg` / `--tabbg` / `--secbg` / `--secborder` / `--border` / `--blendbg`（+ `--bodybg-0`）
   ⚠️ 其中 **`--border` 例外** —— 它现在固定在 Oklch L 0.44，不跟着底色走（见下面那节）。
2. **两份** fade stops 里所有 rgba 的 RGB 三元组
3. `--bodybg-0`
4. 注释里引用的亮度/对比度数字（`--photo-shade` 那段的说明也在内）
5. 文件头"落地"那段的推导

改 `--link` 时：`--helpbutton` + 相关 3~4 处注释。
**手法（换色相不改观感）**：只换色相、保留每条原来的 L / C 和所有 alpha（`oklch2hex(L, C, 新H)`）
→ 正文/链接的对比度一个都不会变。

### ⚠️ `--border` 例外：18 套统一钉在 Oklch L 0.44（2026-10-08）

- **`--border` 不再跟着 `--bodybg` 的明度派生**：全部 18 套统一 `L = 0.44`，**只保留各自的 C / H**
  （推算：`oklch2hex(0.44, 原C, 原H)`；实测 18 套都没有被 sRGB 色域夹掉彩度、色相也不变）。
- **为什么**：官方 `--border #258` 是 **L 0.441 / 对卡片 2.39:1**；各套按底色自己派生的框线只到
  **1.11~2.24:1**，而 `/v<id>/rg`（关系图）里 **节点框、行分隔、节点间的连接曲线与箭头**全部由
  `svg .border { fill:none; stroke: var(--border) }` / `svg .edge polygon.border { fill: var(--border) }` 画出 ——
  这个变量一淡，整张图就只剩文字。**而且节点填充 `--tabbg` 叠在卡片上后与卡片底色亮度完全相同**
  （niimi 实测两边都是 lum 0.0134），没有填充色差可以依靠。→ 框线是这个变量唯一的表现。
- 改完 18 套对卡片的对比度落在 **2.16~2.47**（官方 2.39），层级仍是 `--border`(0.44) < `--secborder`(≈0.47)
  —— 与官方 `--border` 0.441 / `--secborder` 0.472 的关系一致。
  ⚠️ 但 `araya_touka` / `nabari_anju` 这两套的 `--secborder` 原本只有 L 0.441 / 0.447（全家族最暗的两个），
  抬完 `--border` 后两者就撞在一起了（ΔL +0.001 / +0.006，官方是 +0.030）——
  所以这两套的 `--secborder` 也一起抬到 **L 0.470 / 0.471**（`#4d506d → #545681`、`#584f69 → #615378`，
  色相各偏 +1.7° / +1.0°）：ΔL 回到 +0.030，C 比也到了 1.20 / 1.58（官方 1.42）。
  `--border` 与 `--secborder` 的语义差别见文件里的注释：前者是结构线，后者是输入框/浮层框线。
- ⚠️ **以后改 `--bodybg` 不要再把 `--border` 一起重新派生**（§6 第 1 条那个"7 条一起改"里属于它的那一半作废）。

## 7. 换背景图流程

1. 图仓里**沿用旧文件名覆盖内容**（内容哈希名不再反映内容），**只改 CSS 里的 commit SHA**。
2. 同时改 `--theme-bg-h` 的系数（= 新图宽 ÷ 新图高）。
3. **构图重心没变就不用动调色板 / 渐隐方向 / 标题让位**（裁掉一圈四周不影响）。
4. 量尺寸：浏览器打开图片 URL，**页标题里会带 `(WxH)`**（最省事）；或解析 AVIF 的 `ispe` box。
5. 判断"新图到底改了什么"：新旧两版都 `drawImage` 进 canvas，对每个纵向偏移 dy 算平均像素差，取最小者
   （0 附近 = 新图是旧图裁掉 dy 行）。
6. 跑一遍**上线的全量核对**（见第 8 节）。

## 8. 发布 / CDN 约定

- **主题仓库**：`nikaidou-amane/vndb-skins`（public，默认分支 `main`）。
- **图片仓库**：`nikaidou-amane/vn-assets`（2026-10 从 `assets` 改名；旧名 `assets` 现在仍能 200，是重定向）。
- **主题 CSS 一律钉 jsDelivr `@<commit-sha>`**（`max-age=31536000, immutable`，`@main` 只有 7 天，别用）。
  → **改完 css 必须把 `userscript/vndb-daily-skin.user.js` 里 `CDN_BASES` 的两处 SHA 换成含新文件的 commit**，
  否则线上一年内一直是旧文件。
- **脚本自身更新走 `raw.githubusercontent.com`**（`max-age=300`），**不能**用 jsDelivr。
  - 每次改脚本必须升 `@version`（油猴只在远端版本号更高时更新）。
  - raw 的 `content-type: text/plain` → 从链接点安装会被 Chrome 按 MIME 拦，要"从 URL 安装"或拖本地文件。
- 主地址用 **`fastly.jsdelivr.net`**（本机浏览器实测过能加载；不要因为 curl 的表现去改 host）。
- 加/删主题只改脚本里的 `THEMES` 数组 + SHA；**主题数量 N 参与选序，增删会重排之后所有日期**（必然，不是 bug）。
- ⚠️ `raw.githubusercontent.com` 在本机 `curl` 直连不通（不管用）→ **能不能加载一律以浏览器实测为准**。

## 9. 验证方法（怎么"证明"，不靠感觉）

- **一切以浏览器实测为准**：几何、能否加载（`new Image()` 看 `naturalWidth`）、像素颜色、渐变平滑度。
  `curl -sI` 只能当辅助信号。
- **颜色一律用 OKLCh / ΔE00 算**，不靠肉眼判断"像不像"。
  - 参考脚本（纯 stdlib）：hex/rgba → OKLCh、CIEDE2000、WCAG 对比度、`oklch2hex` 带色域收敛。
  - ⚠️ 坑：`Oklab → XYZ` **必须经线性 sRGB**，不能把 Oklab 的 l/m/s 直接当线性 RGB。
    自检：`de00(#000000,#ffffff)=100`、`de00(#ff0000,#00ff00)=86.61`。
- **视觉复核**：把背景图压在新底色上渲一张对照页，截图后目视（旧色/新色并排）。
- **渐变验证**：截跨图片边缘的条带 → 回页内算逐列均值亮度 → 看边界处一阶斜率是否突变。
- **一次性**的探针/预览页**用完就删**（仓库是 public）。
  但下面这几个是**常驻验收工具**，**位置：`.agent/tools/`**：
  `_pal.html`（调色板 + ΔE00/OKLCh 硬指标）、`_probe8.html`（图片尺寸/四缘亮度/色相簇/构图网格实测）、
  `_harness.html`（几何 + 渐隐曲线）、`_skin_mock.html`（单套主题的**仿 VNDB 骨架页**，`?theme=&title=&alt=`）、

  1. 和「把 fade stops 换成两端线性」的**对照组**比：好结果是 S 曲线组在**边界处仍贴着底色**，线性组已经离开 ——

  2. 边界处的 |Δ²|（0.45~0.67）必须**远小于图片自身纹理的 |Δ²|**（3.3~10.3），否则就是肉眼可见的硬边。

     量横向渐隐时可以临时把 `--theme-fade-stops-y` 置成全透明，把纵向那一层隔离掉。
- **几何验收**：在 `_harness.html` 里直接读 `getComputedStyle` —— 渐隐层尺寸必须是 `--theme-bg-w + 4px`、
  图片层是 `--theme-bg-w auto`、`background-origin` 是 `border-box`、`attachment` 是 `scroll`；
